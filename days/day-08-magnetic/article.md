# Day 08：Magnetic 滑鼠跟隨（`gsap.quickTo`）

## 前言

你一定看過，滑鼠靠近某顆按鈕，它會突然像被磁鐵吸住一樣，朝你的方向偏過去，滑鼠一離開又彈回原位。今天要介紹的就是它，**磁吸按鈕**。這種「元素追著滑鼠跑」的互動效果。

> **滑鼠移動時，一秒會觸發上百次事件。這上百次，你打算建立幾個動畫？**

這題的答案，就是今天的主角 `gsap.quickTo()` 存在的理由 🧲

## 為什麼需要 `quickTo`？

要讓元素跟著滑鼠跑，直覺的寫法是監聽 `mousemove`，滑鼠一動就叫元素動過去：

```js
box.addEventListener("mousemove", (e) => {
  gsap.to(box, { x: e.clientX, y: e.clientY, duration: 0.5 });
});
```

但`mousemove` 這個事件**觸發得會非常頻繁**，滑鼠隨便滑一下，一秒就是上百次。等於一秒內對同一個元素狂建上百個 `gsap.to()`。

其實不會怎樣，畫面還是可以正常顯示。只是會很浪費效能。每呼叫一次 `gsap.to()`，GSAP 都要在背後做這些事 ⬇️

- 配一塊新記憶體給這條 tween
- 解析你傳的那包參數（`x`、`y`、`duration`、ease⋯⋯）
- 讀一次 box 現在的起始值
- 把它排進內部的時鐘去跑

等於請了一百個工人，但每個只搬一塊磚就地解散，然後再重雇一百個，在低階手機或滑鼠狂甩時，這就是動畫開始卡卡、跟不上手的來源。

`quickTo` 的用法很簡單：

> 既然目標一直是「同一個元素的同一個屬性」，那就**只建一次** tween，之後每次滑鼠動，不必重建，只需要把新數字餵進去。

## 怎麼做

### `quickTo` 兩步驟：先建立，再餵值

`quickTo` 最關鍵的重點：**它不是做一次動畫，而是生一個可以一直呼叫的函式**。

**第一步，建立**（只做一次，放在 `mousemove` 外面）：

```js
const xTo = gsap.quickTo(box, "x", { duration: 0.5, ease: "power3" });
const yTo = gsap.quickTo(box, "y", { duration: 0.5, ease: "power3" });
```

`gsap.quickTo(目標, 屬性, 設定)` 回傳的**不是動畫，是一個函式**。命名成 `xTo`、`yTo`，一看就知道是拿來設定 x / y 的開關。

> 🕳️ 小提醒：`quickTo` 一次只綁**一個**屬性，所以 x 和 y 要分成兩行、兩個函式。

**第二步，餵值**（每次滑鼠動就呼叫）：

```js
box.addEventListener("mousemove", (e) => {
  xTo(e.clientX); // 把新的 x 目標餵進去
  yTo(e.clientY); // 把新的 y 目標餵進去
});
```

`xTo(300)` 的意思是：x 的目標改成 300，你自己順順地滑過去。滑鼠再動，`xTo(305)`，就從現在的位置接著滑向 305，**全程用的是同一條 tween**，沒有重建。差別不在畫面（跟 `gsap.to` 版本看起來很像），而是在背後省掉的那上百次重建。

### 從「跟屁蟲」到「磁吸」：差一個相對中心的位移

上面那段寫法，box 是直接飛到滑鼠**所在的位置**， demo 左邊那顆綠方塊就是這種，滑鼠在哪它黏在哪。

而右邊的則是，當滑鼠靠近時，元素只朝滑鼠方向**偏移一點點**。關鍵是不用滑鼠的絕對座標，改算 **滑鼠相對元素中心偏了多少**。

**第一步，算滑鼠離中心的距離：**

```js
const r = btn.getBoundingClientRect();
const dx = e.clientX - (r.left + r.width / 2);
const dy = e.clientY - (r.top + r.height / 2);
```

**第二步，乘一個小比例再餵進去：**

```js
xTo(dx * 0.4); // 只跟 40%，不完全貼上去
yTo(dy * 0.4);
```

**第三步，滑鼠離開就回原點：**

```js
btn.addEventListener("mouseleave", () => {
  xTo(0);
  yTo(0);
});
```

因為我們動的是 `x` / `y`（相對位移），回原位就是回到 `0`。這也是磁吸習慣用 `x/y` 而不是絕對定位的原因。

### 三顆手感旋鈕：strength、duration、ease

磁吸好不好看，全看手感，而手感其實是三顆旋鈕在調。demo 下面的控制項可以讓你親手 DIY 這三顆。

**第一顆，`strength`（磁力強度）**，就是上面那個 `0.4`。它決定元素要跟多少：

- 乘 `1`：完全貼上滑鼠，變回跟屁蟲。
- 乘 `0.4`：跟 40%，靠近時偏過去一點。
- 乘 `0.2`：很含蓄，只微微動。

它只是 `mousemove` 裡的一個乘數，**改它不需要重建 quickTo**，所以 demo 的 strength 是即時反應的。

**第二顆，`duration`（追上去要多久）**，寫在 `quickTo` 的設定裡。滑鼠停下後，元素不是瞬間到位，而是花這麼久滑過去：

- 數字越大：越**黏、拖尾**，有種被濃稠磁場拉著的感覺。
- 數字越小：越**跟得緊、乾脆**。

**第三顆，`ease`（追的過程快慢）**，也在設定裡。等速（`linear`）會有點死板，`power3` 是先快後慢。

> 🕳️ 小提醒：`duration` 和 `ease` 是 `quickTo` **建立時就固定**的設定。也就是說，改這兩個必須重新 `gsap.quickTo(...)` 建一條新的。

### 讓感應區比按鈕大一點

滑鼠要多靠近，磁吸才開始有反應？這其實是我們自己決定的，關鍵在 `mousemove` 綁在**哪個元素**身上。

如果直接綁在按鈕本身：

```js
btn.addEventListener("mousemove", (e) => {
  /* ... */
});
```

那只有滑鼠**真的壓在按鈕上**，事件才會觸發，磁吸要等到碰到了才開始動，感覺會慢半拍、鈍鈍的。

如果改綁在一個**包住按鈕、範圍更大**的外層容器上，滑鼠一踏進這個大範圍，事件就先觸發了！

```html
<div class="magnetic-area">
  <!-- 這一圈比按鈕大，是感應範圍 -->
  <button class="magnetic-btn">Hover 我</button>
</div>
```

```js
// 綁在外層的 area，不是按鈕本身
area.addEventListener("mousemove", (e) => {
  /* ... */
});
```

demo 裡磁吸那格的虛線框，就是這個放大的感應範圍。滑鼠一踏進虛線框，還沒真的碰到藍色按鈕，磁吸就已經開始拉了。這就是磁吸看起來很有魔力的原因～～

### 回彈的過衝，疊在 scale 上

到這裡磁吸已經會動了，但離開時只是平順地滑回原點，少了點彈性。如果想要有點Q彈、稍微過頭的感覺，這要靠 `back` 這系列的 ease。

我一開始想偷懶，直接把 `quickTo` 的 ease 換成 `back.out`，結果動起來怪怪的。原因是因為滑鼠移動時 `quickTo` 是連續一直被餵新目標的，目標一直換，`back` 那種會先衝過頭再彈回來的感覺還沒結束，下一次又來了，視覺上就會抖抖、怪怪的。那如果是`back` 這種有回彈感的 ease，也比較適合用在「只跑一次、有終點可以彈」的動畫，不適合應用在連續跟隨的場景。

那如果換一顆一次性的 `gsap.to` 去做 x/y 的回彈呢？答案是不行：這條新的 tween 動的還是同一個元素的 x/y，跟 `quickTo` 內部自己管的那條 x/y tween 會搶同一個屬性，一旦讓它蓋過去，`quickTo` 就會被砍死，之後怎麼呼叫都不會有反應。

真正乾淨的做法，是把過衝效果**換一個屬性**，直接避開跟 `quickTo` 搶地盤：

```js
function onMagneticLeave() {
  // 位置交給 quickTo 自己滑回原點，平順但沒有過衝
  xTo(0);
  yTo(0);
  // 過衝的彈性感，改疊加在 scale 上，跟 x/y 是不同屬性，不會互搶
  gsap.fromTo(
    btn,
    { scale: 1.12 },
    { scale: 1, duration: 0.4, ease: "back.out(2)" },
  );
}
```

位移(x/y)交給 `quickTo`，全程平順不被打斷；縮放(scale)負責彈性，用一次性的 `gsap.fromTo` 疊加過衝手感。兩邊各自管各自的屬性，永遠不會互搶。

> 🕳️ 小提醒：想在同一個元素上疊加兩種手感時，與其硬要在同一個屬性上兼顧兩種需求，改用不同屬性分工通常更乾淨。位移負責跟手、縮放或旋轉負責彈性，是磁吸按鈕常見的搭配～～

### 兩個延伸小知識

**第一個，`quickTo` 還有一個雙胞胎 `quickSetter`。** `quickTo` 是「給目標，柔滑滑過去」（有 `duration`）；`quickSetter` 是「給多少，瞬間就是多少」（0 秒到位）。磁吸要柔滑跟隨，所以用 `quickTo`；哪天你要做「瞬間貼死滑鼠」那種效果，就換 `quickSetter`。

**第二個，你可能會想：自己對 `mousemove` 做節流（throttle）不就好了？** 好消息是 `quickTo` 內部已經接上 GSAP 的動畫時鐘（ticker）幫你處理，你餵再多次值，它也只會在每一幀真正更新一次，不用自己寫 `requestAnimationFrame` 去節流 👍

## 小結

今天讓元素黏上了滑鼠，也認識了高頻更新的 `quickTo` 🧲

| 想做的事           | 用什麼                             | 白話                           |
| ------------------ | ---------------------------------- | ------------------------------ |
| 高頻更新同一個屬性 | `gsap.quickTo()`                   | 只建一次，之後一直餵值，不重建 |
| 一次綁一個屬性     | x 一個、y 一個                     | quickTo 不吃一整包 `{ x, y }`  |
| 從跟屁蟲變磁吸     | 算相對中心的 `dx/dy` × strength    | 不用絕對座標，用相對位移       |
| 磁吸更有魔力       | 感應區綁在比按鈕大的容器           | 還沒碰到就開始吸               |
| 離開的過衝回彈     | 過衝疊在 `scale`，位置留給 quickTo | 不同屬性分工，不會互搶         |
