# Day 11：GSAP 動畫控制：讓動畫聽你的話

昨天我們自己畫了一條 ease 曲線，把動畫的手感捏成想要的樣子。但你有沒有發現，到目前為止我們寫的每一個動畫，都是**寫下去就一路跑完**，中間完全插不了手？

想讓它停在中間看仔細一點？沒辦法。想放慢兩倍慢慢欣賞？沒辦法。想直接跳到最後那一段？也沒辦法。

今天來認識要怎麼處理！首先要知道一件事

> **`gsap.to()` 會回傳一個東西。**

## 動畫不是一個動作，是一台播放器

前面十天我們都這樣寫：

```js
gsap.to(".box", { x: 300, duration: 2 });
```

寫完就沒事了，方塊自己會動，但這行其實有回傳值，只是我們一直沒接住它。

```js
const tw = gsap.to(".box", { x: 300, duration: 2 });
```

這個 `tw` 是什麼？可以把它想像成一台**播放器**。方塊會動，是因為它正在播。既然是播放器，我們就能對它下指令：暫停、倒轉、跳到某一段、放慢速度。

timeline 也一樣 👇

```js
const tl = gsap.timeline();
tl.to(".box", { x: 300, duration: 1 }).to(".box", {
  rotation: 360,
  duration: 1,
});
```

`tl` 也是一台，只是能裝好幾段。

其實 Day 7 做 hover 時我們就偷用過一次了。那天把 timeline 先 `paused: true` 存起來，滑鼠進來 `play()`、滑出去 `reverse()`，當時只是照著寫，今天把它講完整。

### 先複習一下基本的四顆按鈕

播放器最基本的四顆，差別在**播放頭往哪走、從哪開始**：

```js
tl.play(); // 從現在的位置往前播
tl.pause(); // 停住，位置保留
tl.reverse(); // 從現在的位置倒著播回起點
tl.restart(); // 跳回起點，重新播一次
```

三個容易搞混的地方：

- **`pause()` 不會歸位。** 它停在當下，方塊維持演到一半的樣子，不會跳回原狀。
- **`play()` 和 `restart()` 差在起點。** 播到一半 `pause()` 再 `play()`，會從一半繼續；`restart()` 則是回到 0 重播。所以重播按鈕要用 `restart()`，用 `play()` 在動畫已經播完時會完全沒反應，因為播放頭在終點，沒東西可播了。
- **`reverse()` 不是播一個反向動畫。** 它是把同一條倒著跑，所以 ease 也跟著倒。進場是先快後慢，倒回去就變成先慢後快，手感會跟你想的不一樣（這點 Day 7 有提過）。

這四顆管的是**有沒有在跑**。接下來三顆旋鈕管的是**跑多快**和**跑到哪**，不同維度，可以疊著用。

> 🕳️ 小提醒：**動畫一定要存成變數，之後才有東西可以下指令。** 這聽起來像廢話，但很多人第一次想控制動畫時，會回頭去找那個 DOM 元素，然後發現不知道怎麼辦。要控制的不是元素，是那台播放器。

## 第一顆旋鈕：`timeScale()`，控制跑多快

`timeScale` 是速度倍率，1 是正常速度：

```js
tl.timeScale(2); // 兩倍速，快轉
tl.timeScale(0.5); // 半速，慢動作
```

它是**乘上去的倍率**，不是重新設定 duration。所以一條 3 秒的 timeline 設成 `timeScale(2)`，實際會在 1.5 秒內跑完，但你去問它 `duration()`，它還是回答 3。

好玩的來了。既然 `timeScale` 是個能改的值，那它自己也能拿來做動畫：

```js
// 花 0.5 秒，把速度平滑地降到 0.2 倍
gsap.to(tl, { timeScale: 0.2, duration: 0.5 });
```

注意 `gsap.to()` 的第一個參數這次不是 DOM 元素，是 `tl` 這條 timeline 本身。GSAP 不在乎你給它什麼，只要那個東西身上有你想動的屬性就行。

這招是很多網站「滑鼠移上去畫面就進入慢動作」的做法，比直接 `timeScale(0.2)` 硬切自然很多。

## 第二顆旋鈕：`progress()`，控制跑到哪

今天最重要的就這一段。表面上在講進度，其實藏著一條 GSAP 到處都在用的規則。

`progress` 是進度，一個 0 到 1 的數字：

```js
tl.progress(); // 回傳 0.37，意思是跑了三成七
tl.progress(0.5); // 直接跳到一半
```

**同一個名字，有沒有丟參數進去，做的事完全相反。**

- 不給參數 = **讀**，它回答你現在跑到哪
- 給參數 = **寫**，它跳到你指定的位置

這叫 getter / setter 兩用，而且不只 `progress`，GSAP 一整排方法都吃這套：

```js
tl.timeScale(); // 讀：現在幾倍速
tl.timeScale(2); // 寫：改成兩倍速

tl.duration(); // 讀：總長幾秒
tl.time(); // 讀：現在第幾秒
tl.time(1.5); // 寫：跳到第 1.5 秒
```

學會一個等於學會全部，這條規則之後每天都會用到。

### 讀來幹嘛？先問狀態，再決定要做什麼

寫（叫它跳到某處）比較好想像，讀的用途新手常常想不到，所以先講一個很實際的。

假設你做一顆播放按鈕，無腦寫成這樣：

```js
playBtn.addEventListener("click", () => tl.play());
```

動畫播完之後再按，你會發現**完全沒反應**。因為播放頭已經停在終點了，`play()` 往前播也沒東西可播。這時候就要先問它一句：

```js
playBtn.addEventListener("click", () => {
  if (tl.progress() === 1) return tl.restart(); // 讀：已經播完了？那改成重播
  tl.play();
});
```

**先讀、再判斷、再下指令**，這就是 getter 存在的意義。今天 demo 的 play 鈕就是這樣寫的。

### 用它做一個進度條

`progress()` 最常見的用途就是進度條，而且讀跟寫都會用到。

**讀**的那半邊，拿來顯示：

```js
const bar = document.querySelector(".bar");
bar.style.width = tl.progress() * 100 + "%";
```

**寫**的那半邊，拿來讓使用者拖：

```js
slider.addEventListener("input", () => {
  tl.pause(); // 先暫停！
  tl.progress(slider.value / 100); // 再跳位
});
```

> 🕳️ 小提醒：**拖之前一定要先 `pause()`。** `progress(0.5)` 只是把播放頭搬到一半的位置，如果 timeline 本來就在播，它下一幀就繼續往前跑了。你會看到方塊跳過去之後，手還沒放開就自己溜走。

再補兩個很容易踩到的細節：

```js
tl.progress; // ❌ 沒加括號，拿到的是函式本身，不是數字
tl.progress(); // ✅ 讀
```

```js
tl.progress(0).pause(); // ✅ 可以串起來
```

第二個之所以能串，是因為 setter 回傳的是 timeline 自己，不是數字。這也剛好解釋了為什麼讀跟寫共用一個名字還不會打架。

順帶預告一下：**`progress()` 是之後 ScrollTrigger 的地基。** 那個讓動畫跟著捲軸走的效果，底層做的事就是把捲動位置換算成一個 0 到 1 的數字，然後餵給 `progress()`。

## 第三顆旋鈕：`seek()` 加 label，用書籤跳位

`progress()` 是按比例跳，`seek()` 是按秒數跳：

```js
tl.seek(1.5); // 跳到第 1.5 秒
```

但按秒數有個麻煩。你之後在前面插一段新動畫，後面寫死的秒數就全歪了。所以 GSAP 讓你在時間軸上下**書籤**（label）：

```js
const tl = gsap.timeline();

tl.addLabel("移動")
  .to(box, { x: 280, duration: 1 })
  .addLabel("旋轉")
  .to(box, { rotation: 360, duration: 1 })
  .addLabel("變色")
  .to(box, { scale: 1.5, backgroundColor: "#f472b6", duration: 1 });

tl.seek("旋轉"); // 跳到那個書籤，不用管它在第幾秒
```

之後不管你怎麼調整前面的段落，`seek("旋轉")` 永遠跳得到對的地方。timeline 越長，這個好處越明顯。

> 🕳️ 小提醒：**`seek()` 預設不會觸發 callback，但 `progress()` 會。** 這兩個方法都有第二個參數叫 `suppressEvents`，意思是要不要把過程中的事件關掉。`progress()` 的預設是 `false`（照常觸發），`seek()` 的預設卻是 `true`（統統關掉）。
>
> 我做這天的 demo 就遇到了，按書籤跳位時方塊明明動了，旁邊那個靠 `onUpdate` 更新的進度數字卻卡住不動，看起來像壞掉。解法是自己把它打開：
>
> ```js
> tl.seek("旋轉", false); // 第二個參數傳 false，事件就會照常觸發
> ```

## 動畫演到哪了：四個 callback

前面三顆旋鈕是我們對動畫下指令。這一組反過來，換動畫來通知我們。

四個時間點，都寫在設定物件裡：

```js
gsap.to(".box", {
  x: 300,
  duration: 2,
  onStart: () => console.log("開始跑了"),
  onUpdate: () => console.log("每一幀都會叫我"),
  onComplete: () => console.log("正向跑完了"),
  onReverseComplete: () => console.log("倒帶回到起點了"),
});
```

最常見的用途是收尾工作：動畫演完才解鎖按鈕、動畫演完才把元素移除、動畫演完才播下一段。

三個要注意的地方：

**1. 倒著播不會觸發 `onComplete`。**

這個超容易搞混。`onComplete` 只認**正向**跑到底，`reverse()` 倒帶回起點觸發的是 `onReverseComplete`。像 Day 7 那種進場離場的 hover 寫法，很容易寫錯地方，然後怎麼調都沒反應。

**2. `onUpdate` 一秒會跑六十次。**

每一幀觸發一次。裡面塞太重的東西，像是改一堆 DOM、算複雜的數學，畫面就會卡。之後講動畫效能時還會再遇到它，先記著。

**3. `onStart` 不是只觸發一次。**

它指的是從靜止變成在跑的那一刻。所以 `restart()`、`reverse()` 這些讓它重新動起來的操作，都會再觸發一次。

## 小結

動畫從寫下去就跑完，變成隨時聽你指揮 🎮

| 想做的事         | 用什麼                             | 白話                                 |
| ---------------- | ---------------------------------- | ------------------------------------ |
| 之後要能控制它   | `const tl = gsap...`               | 沒存起來就沒東西可以下指令           |
| 跑、停、倒、重來 | `play` `pause` `reverse` `restart` | 管的是有沒有在跑，重播要用 `restart` |
| 調快調慢         | `tl.timeScale(2)`                  | 乘上去的倍率，不是改 duration        |
| 平滑地變慢       | `gsap.to(tl, { … })`               | 連倍率本身都能做動畫                 |
| 問它跑到哪了     | `tl.progress()`                    | 不給參數就是讀，回傳 0 到 1          |
| 叫它跳到某個進度 | `tl.progress(0.5)`                 | 給參數就是寫，瞬間跳過去             |
| 按書籤跳位       | `tl.seek("旋轉", false)`           | 比寫死秒數耐改，記得補 `false`       |
| 動畫演完要做事   | `onComplete`                       | 倒帶回起點是 `onReverseComplete`     |
| 每一幀都要做事   | `onUpdate`                         | 一秒六十次，別塞太重的東西           |

整張表最該記住的其實是那條 getter / setter 規則：**有沒有丟參數進去，決定它是讀還是寫。** 這條在 GSAP 到處都成立，之後不用再學第二次。

話說回來，今天講的都是怎麼讓動畫照你的意思動。但有時候我們要的不是控制它，是讓它**別再動了**。這件事比想像中容易出事，我 Day 7 做 demo 時就這樣把整個 hover 效果弄壞過一次，下一篇來講這個 👋
