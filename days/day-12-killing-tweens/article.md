# Day 12：GSAP 動畫終止：kill、killTweensOf 與 overwrite

## 前言

這篇是「人要可愛，網頁也要動感迷人系列」的 Day 12，感謝大家的觀看嘻嘻～

前一篇我們學會把動畫當播放器操控，想暫停就暫停、想跳哪就跳哪。今天要學的則是**叫它別動了**。

聽起來很簡單（？）感覺好像用`pause()` 一下不就好了。但這件事其實比想像中更複雜～

## 首先，先立一個問題：要砍掉的單位是誰

停掉動畫的方法有好幾種，它們的差別是**砍下去範圍多大**：

| 方法                    | 單位是         | 白話                   |
| ----------------------- | -------------- | ---------------------- |
| `tween.kill()`          | **那一條動畫** | 我手上這條，砍它       |
| `gsap.killTweensOf(el)` | **那個元素**   | 這個元素身上的，全砍   |
| `overwrite: "auto"`     | **衝突的屬性** | 只砍跟我搶同一個屬性的 |

範圍越大越方便，也越容易誤傷。我在 Day 7 的時候就曾經不小心砍的範圍太大，導致其他動畫壞掉。

## `kill()`：砍那一條

最單純的一種。你手上握著哪條動畫，就砍哪條，範例如下：

```js
const tw = gsap.to(".box", { x: 300, duration: 2 });

tw.kill(); // 這條從此消失
```

這裡的消失是真的消失。GSAP 會把它從排程裡移除、釋放掉，所以**它跟 `pause()` 完全不是同一件事**：

```js
tw.pause(); // 停住，之後 play() 還能接著跑
tw.kill(); // 死了，之後 play() 不會有任何反應
```

> 🕳️ 小提醒：**被 kill 的元素會卡在動畫演到一半的位置。** 直覺會以為動畫砍掉，元素就會回到原狀，不會。動畫跑到哪，它就停在哪，而且 GSAP 寫進去的 inline style 還留在元素上。想真的歸位要用別的方法，後面會講到。

`kill()` 也可以只砍一部分，第二個參數指定屬性：

```js
tw.kill(".box", "x"); // 只砍掉這條 tween 裡跟 x 有關的部分，其他照跑
```

這個平常用不太到，知道有就好。

## `killTweensOf()`：砍掉整個元素，整個喔！

有時候你手上沒有那條動畫的變數。例如動畫是在某個 event handler 裡臨時建的，建完就沒存起來，這時候只能從元素下手：

```js
gsap.killTweensOf(".box"); // 這個元素身上的動畫，全砍
gsap.killTweensOf(".box", "x,scale"); // 也可以只砍動這兩個屬性的
```

雖然方便，但**它的單位是元素**，這就是我在 Day 7 出事的原因。

當時每張卡片都有一條常駐的 timeline（先 `paused`，滑鼠進來 `play()`、滑出去 `reverse()`）。我想在切換模式時把殘留的臨時動畫清乾淨，就寫了這行：

```js
gsap.killTweensOf(card); // 我以為只會砍掉臨時的那幾條
```

結果 hover 整個死掉。因為那條常駐 timeline 裡的 `tl.to(card, {...})`，**本身也是一條掛在 `card` 身上的 tween**，被一起連坐砍了。timeline 被掏空之後 `play()` 就沒東西可播，偏偏物件還在、方法也照樣呼叫得到，但畫面就是不動。

正解是別用範圍這麼大的工具：把臨時動畫存成變數，再用 `kill()` 精準砍它。

## `overwrite`：讓 GSAP 自動幫你砍

前面兩個是你主動砍。`overwrite` 則是設定在新動畫上，讓它出生時自動清掉舊的。三個值：

```js
gsap.to(".box", { x: 0, overwrite: false }); // 預設，誰都不砍
gsap.to(".box", { x: 0, overwrite: true }); // 同元素的全砍
gsap.to(".box", { x: 0, overwrite: "auto" }); // 只砍屬性衝突的
```

光看文字很難有感，所以今天的 demo 特地做了一顆**身上掛兩條動畫**的球：一條讓它往右移動（動 `x`），一條讓它一直轉（動 `rotation`）。然後發射一條新的 tween，**只動 `x`**，把球往左拉回去。

旋轉跟這條新 tween 一點關係都沒有。來看三個值各自會發生什麼。

### `false`：誰都不砍，於是打架

新舊兩條 tween 都活著，而且都在搶同一個 `x`。

```
發射前   x = 95
發射後   x 被拉回 0        ← 新的看起來贏了
1 秒後   x 突然跳到 238    ← 舊的那條從沒死，它接手了
```

新 tween 只有 1 秒，它一結束，那條被冷落但從沒被砍掉的舊 tween 立刻奪回控制權，把球扯回右邊。

**這就是 Day 7 鬼影的完整真相。** 當時 hover 進去放大到一半就滑走，離場動畫看起來贏了，但沒跑完的進場動畫還活著，它一有機會就把卡片又放大回去。

### `true`：全砍，包括無辜的也受牽連

```
x         被拉回 0    ← 符合預期
rotation  停住不轉    ← 咦？
```

新 tween 明明只寫了 `x`，旋轉卻莫名其妙停了。因為 `overwrite: true` 的意思是把這個元素身上其他 tween 全部砍掉，它**根本不看屬性**。

這跟 `killTweensOf()` 是同一種連坐，只是換個地方發生。

### `"auto"`：只砍衝突的

```
x         被拉回 0    ← 舊的位移被砍掉了
rotation  繼續轉      ← 活下來了
```

`"auto"` 會去比對屬性：只砍掉**正在跑、而且動同一個屬性**的部分，不衝突的留著。這通常就是你要的。

> 🕳️ 小提醒：`true` 和 `"auto"` 的差別，只有在同一個元素身上有多條動畫時才看得出來。如果球身上只有位移那一條，兩個值的結果會一模一樣，你會覺得它們沒差別。真正會影響到的場景是常駐動畫加臨時動畫混用，也就是 Day 7 那種。

順帶一提，兩者的使用時機也不同：`true` 是**建立的當下**立刻砍，`"auto"` 是**第一次 render 時**才砍。

## `revert()`：不只停掉，還要還原回去

前面說被 kill 的元素會卡在半路。如果想讓它真的回到動畫前的樣子呢？

```js
tw.revert();
```

這裡要修正一個很容易有的直覺：**`revert()` 不是 `kill()` 的另一個選項，它是 `kill()` 再多做一件事。** 它會撤銷這條動畫並且把它 kill 掉，讓目標回到動畫前的樣子，包含**把動畫寫上去的 inline style 移除**。

所以：

|            | 動畫沒了     | 位置         | GSAP 寫的 inline style |
| ---------- | ------------ | ------------ | ---------------------- |
| `pause()`  | 沒有，還活著 | 停在半路     | 還在                   |
| `kill()`   | ✅           | 停在半路     | **還在**               |
| `revert()` | ✅           | **回到起點** | **被清掉**             |

今天 demo 第一部分，會有四顆球同時起跑，中途按一顆鈕讓它們各自遭遇一種下場，畫面下方會直接印出每顆球的 `element.style.transform`，你可以看到 `revert()` 那顆變成空的，其他三顆的 transform 都還在。

### 那 `progress(0)` 不就好了？

昨天學過 `progress(0)` 可以把動畫倒回起點，看起來好像一樣？但這兩個差很多：

```js
tw.progress(0); // 畫面回到起點，但 inline style 還留在元素上
tw.revert(); // 連 inline style 一起清掉
```

差在哪？如果元素的樣式本來是 CSS 決定的，殘留的 inline style 權重比較高，會一直蓋著你的 CSS。之後想用 class 切換樣式就會發現改不動。

> 🕳️ 小提醒：**順序不能顛倒，`kill()` 之後就 revert 不回來了。** 我做 demo 時實測到的：對還活著的動畫呼叫 `revert()`，inline style 清得乾乾淨淨；但如果先 `kill()` 再 `revert()`，transform 就留在元素上清不掉了。因為 `kill()` 會把動畫釋放掉，`revert()` 需要的那份動畫前的紀錄也跟著沒了。
>
> ```js
> tw.revert(); // ✅ 清得掉
>
> tw.kill();
> tw.revert(); // ❌ 來不及了，清不掉
> ```
>
> 想還原就直接使用 `revert()` 吧！

`revert()` 真正的威力要配 `gsap.context()` 才看得出來，那是元件層級整包收掉的做法，留到之後再講～今天先知道它跟 `kill()` 差在哪就好。

## 小結

**砍動畫的時候，要先想清楚砍的單位是誰。**

| 想做的事             | 用什麼                  | 單位                           |
| -------------------- | ----------------------- | ------------------------------ |
| 停一下等等再繼續     | `tween.pause()`         | 那一條（沒砍，只是停）         |
| 砍掉我手上這條       | `tween.kill()`          | 那一條                         |
| 砍掉這元素身上全部   | `gsap.killTweensOf(el)` | 元素，**會連坐**               |
| 新動畫自動清舊的     | `overwrite: "auto"`     | 衝突的屬性                     |
| 同上但不管三七二十一 | `overwrite: true`       | 元素，**會連坐**               |
| 停掉並且還原成原狀   | `tween.revert()`        | 那一條，連 inline style 一起清 |

兩個會連坐的用法要特別小心，尤其是元素身上同時有常駐動畫和臨時動畫的時候。真的想精準，就把動畫存成變數再用 `kill()`，這是最不會誤傷旁邊的做法。

到目前為止我們的動畫都是播一次就結束。但很多效果是要一直重複的，像 loading 轉圈、呼吸般的縮放、無限跑的跑馬燈。下一篇來看看怎麼讓動畫循環，我們下篇見 👋
